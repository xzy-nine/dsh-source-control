# Agent Note: AI 提交信息的输入取舍

Status: implemented

## Problem

生成提交信息时，整份 diff 被切成文件块后一律按长度升序填进总预算。这带来四个具体后果：

- 二进制文件的 diff 块（`Binary files ... differ` 或替换字符乱码）与文本块同权参与排序，占掉预算却不提供可用信息；
- 文档改动与代码改动同权，一个大的 Markdown 表格可能挤掉真正的代码改动；
- 合并提交与普通提交用同一条路径，模型只看得到 diff，看不到被合并进来的分支说了什么，而合并提交的意图恰恰记在那条历史信息里；
- 超出总预算的文件被静默丢弃，用户不知道模型少看了哪些文件。

## Decision

`commit-diff.ts` 收集、`ai-commit-request.ts` 组装，`collectDiff` 返回 `{ diff, binary, merged, dropped }` 而不是一段字符串。

### 二进制文件只留文件名

判据取 git 自己的结论：`--numstat` 的增删列同时为 `-` 即二进制。未跟踪文件没有 numstat 记录，改按文件头部 8000 字节内是否含 NUL 判定。二进制块的内容不进提示词，路径进单独一段清单，因此纯二进制改动（换图、换资源）同样能生成提交信息 —— 此前这类改动会让 diff 为空而直接报错。

### 文档排在代码之后

文档扩展名取 `md` / `markdown` / `txt` / `rst` / `adoc` / `org`，只看文件名的最后一个扩展名。填充顺序是「代码块按长度升序 → 文档块按长度升序」：预算充足时两者都进，吃紧时先丢文档。因上限未进入的文件按 `document`（文档让位）与 `budget`（超出总量）记入 `dropped`。

### 合并提交先给历史

合并进行中取 `MERGE_HEAD` 指向的提交（每行一个，章鱼合并因此有多行）；修补上一次提交且该提交本身是合并提交时，取 `rev-list --parents` 的第二父提交起。两者的短哈希与完整信息用 `log --no-walk=unsorted -z --format=%h%x00%B` 一次取回。请求按「被合并入的提交 → 二进制清单 → diff」三段拼接，提示词要求模型先据历史概括合并目的、diff 只补充细节。

### 超长丢弃向用户报告

`dropped` 经 `droppedNotice` 变成一段告警，走既有的 `warning` 事件显示在提交框告警行，并同时写进宿主日志。列举上限 20 个文件，其余按总数说明。

## Alternatives considered

**二进制文件完全排除，文件名也不出现。** 否决：模型将无从得知这类改动的存在，换图的提交会得到一条只描述其他文件的提交信息。

**保留 git 的 `Binary files ... differ` 单行。** 否决：信息量与文件名清单相同，但要求解析 diff 头部的 `a/… b/…` 形式；含空格的路径在那里无法无歧义还原，而 numstat 已经给出干净的路径。

**文档按「除代码扩展名以外的一切文本」判定。** 否决：需要维护代码扩展名清单，新增语言时必然漏更新；白名单只覆盖写作类文件，配置与 lock 文件仍按代码处理。

**只要有代码块，文档块一律不进提示词。** 否决：纯文档仓库的提交信息会失去文档改动信息，而用户往往希望提交信息覆盖文档更新。

**被合并入的提交只取标题行。** 否决：合并分支的正文说明（动机、影响面）恰是生成合并提交信息最有用的输入。

**把丢弃清单也写进提示词让模型知情。** 否决：模型看不到这些改动的内容，告知它只会诱导它按文件名猜测。

**沿用返回字符串的 `collectDiff`，在路由里再解析分类。** 否决：分类信息在切块时就有，重新从文本推断会把已经知道的事实再猜一遍。

## Consequences

**收益**：二进制改动不再挤占预算且可单独生成；代码改动优先保住；合并提交的生成依据是被合并分支自己的提交信息；用户能看到模型少看了哪些文件。

**代价**：

- 提示词 JSON 多两段模板（`merged` / `binary`），`data-sources.test.mjs` 的形状校验随之覆盖。
- `collectDiff` 的返回类型改变，调用方必须按字段取用；`test/ai-commit-diff.test.mjs` 全部断言改为读 `collected.diff`。
- 二进制判定对未跟踪文件要读文件头部，未跟踪文件很多时会多出等量读取；沿用既有逐文件构造 patch 的代价。
- 文档扩展名是白名单，新增文档格式需要同时改这里。
- 这条契约的正家是 `Docs/功能/AI提交信息.md`，`Docs/实现/代码结构.md` 只列举两个模块与指向该页的链接；改判定或上限时两者要一起看。

## Testing

- `test/ai-commit-diff.test.mjs`：二进制只留文件名（含未跟踪二进制）、代码排在文档之前、超预算时文档记 `document` 而代码记 `budget`、`MERGE_HEAD` 与第二父提交两种合并来源、非合并提交不产生合并段、文档扩展名与二进制判定的纯函数用例。把 `fillBudget` 的代码/文档两段合并、让二进制重新进入填充、把 `document` 原因改成 `budget`、去掉 `MERGE_HEAD` 分支，四处各让对应用例变红。
- `test/ai-commit-request.test.mjs`：三段顺序、多个被合并入提交逐条列出、二进制清单排在 diff 之前、修补模板、丢弃说明的列举上限与总数。
- 既有 `test/data-sources.test.mjs` 校验提示词各段非空且占位符可用。
