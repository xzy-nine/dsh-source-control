# Agent Note: 泳道按行压实以固定提交信息列

Status: implemented

## Problem

图形区的提交信息起点由本行泳道数决定：`lanes.ts` 的 `laneSpanWidth(row.width)` 决定泳道单元格宽，消息紧接其后。泳道只增不减时，一次合并把行宽推到三条泳道后，后续所有行即使只剩一条泳道也保持三格宽，消息列因此逐次右移且不再回移。实测本仓库最近 40 行：第 0 行宽 1，第 2 行起宽 3，第 11 行起宽 4 并一直保持到页尾，而末态只剩 3 条等待中的泳道。

## Decision

`layoutCommits` 在每行结束时压实：`output` 中 `hash` 为 null 的空位与占位泳道（无父提交的节点留下的）就地移除，其余泳道按原顺序左移，压实后的数组作为下一行的输入。行内线段因此分两类：行顶下标即输入位置，行底下标取压实后的落点，两者不同就是一段 S 形平移。

行宽取 `max(input.length, compacted.length, nodeLane + 1, 1)`，随分支结束回落。提交信息起点仍按本行泳道数排布（`laneSpanWidth`），不改成跟随节点泳道：分支未合并期间节点右侧仍有别的泳道线，消息紧跟节点会压在线上。

`bottomOf` 只改变行底落点，节点自身位置仍在行顶泳道上；汇入本行的线段终点是节点，不参与压实位移。同一行内的平移段按起点顺序映射到落点顺序，因此互不交叉，几何上是一次整体左移。

## Alternatives considered

**消息列固定为本次加载中的最大泳道宽度。** 否决：列不随行漂移，但整列位置随「加载到的最宽行」变化，滚动加载更多历史时列会整体跳一次；压实后行宽本就回落，固定列的收益消失，代价是短行在图形与文字间留出大片空白。

**消息紧跟节点所在泳道。** 否决：分支存活期间节点右侧仍有别的泳道贯穿线，文字会压在线上。

**只在显示层修消息列，不动布局。** 否决：行宽只增不减的根因是泳道表只追加不回收；不改布局只能让消息列与图形脱钩，图形本身仍会在窄分支上右侧留空。

**按行整表左移（所有行统一到全图最小宽度）。** 否决：泳道数少的行会让未结束的泳道被迫平移，行间频繁出现 S 形曲线，分支线的横向位置不再可追踪。

## Consequences

行宽随分支结束回落，消息列不再停在历史最宽处；图形区在窄分支上收回右侧空白。代价是分支结束的行会出现 S 形平移段，与参考实现（提交图不压实）的观感不同；跨行连续性测试相应改为断言「平移只向左、同行不交叉」。

压实只移除无归属的泳道，未结束的泳道（含分页外父提交占住的泳道）之间的相对顺序保持不变，各自的行底落点由左侧被移除的槽位数决定。分页加载后已渲染部分的行不变，因为布局只依赖本行之前的输入；窗口变长不改变既有行之前的处理。

## Testing

`test/diff/lanes.test.mjs`：「泳道释放后右侧泳道左移一格」断言平移段存在、只向左且同行不交叉；「分支结束后行宽回落到实际并发泳道数」断言合并行宽 2、末行宽 1。把压实改回「全表保留」两条都会变红。

「每条向下延伸的线都在下一行被接续」与「压实后行间的泳道与颜色仍然连续」保持原样并通过：压实后的行底下标就是下一行的行顶下标。
