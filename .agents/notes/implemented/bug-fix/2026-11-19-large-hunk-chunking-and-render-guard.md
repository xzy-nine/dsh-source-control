# Agent Note: 差异页按块切分与正文渲染守卫

Status: implemented

## Problem

侧栏差异页渲染某个超大文件时变成空白，此后同一页类型打开的其它文件也全是空白。两段因果都要处理。

第一段是渲染路径：forge 的 `DiffFile` 把一块差异的行按展开参数一次性交给 `Array.prototype.push`（`diff-rows.ts` 的 `rows.push(...hunkRows(hunk))`，单行布局下另有 `DiffFile.tsx` 的 `rows.push(...commentsAt(...))`）。展开的实参个数等于该块的可见行数，单块行数超过运行时实参上限即抛 `RangeError: Maximum call stack size exceeded`。实测在 Node v24 上约 12.5 万行触发，整文件重写或完整删除的文件恰好会产出一个这样的块。

第二段是失败范围：宿主给侧栏页正文套的错误边界按页类型收回注册（ui-slots 的 `reportEntryError` 带 `abdicate`），`single`/keyed 类型一崩即从该页类型的登记里退役。退役是整页类型一次性的，因此「一个文件渲染失败」被放大成「此类页面从此都画不出内容」，页头与文件切换也随之消失，用户只能重新加载。

## Decision

两段各自收口。

渲染路径由 `client/diff/hunk-chunking.ts` 的 `chunkHunks` 把块切到 `MAX_HUNK_LINES`（4000 行）以内，`forge-adapter.tsx` 的 `toForgeHunks` 是唯一入口。切分按行首字符推进两侧行号：加号只增新侧，减号只增旧侧，空格两者都增，反斜杠开头的「文件末尾无换行」标记两者都不增且留在它前一行所在的块里。小块首尾相接，行号连续，因此 forge 算出的折叠区段与切分前一致；未超限的块不切。

失败范围由 `client/diff/render-guard.ts` 的 `DiffRenderGuard` 收住：它包住 `GitDiffTab` 的正文，渲染错误改画成一段说明与「重试」按钮，页头、文件下拉与换行/跳转控件留在原位。守卫按「作用域 + 文件路径」当 key 重新挂载，上一个文件的失败不跟到下一个文件。

## Alternatives considered

**在宿主侧就截断超长 hunk。** 否决：hunk 的内容与行号是差异语义本身，截断会让行号、折叠区段与分段暂存下标一起失真；分页与「已截断」标记又要新增一套界面状态。切分只改变块的边界，不动内容。

**把大文件标成 `oversized`，让 forge 画「文件太大」提示。** 否决：forge 的 `oversized` 语义是「未跟踪文件超过体积上限，没有 hunk」，与「有完整 hunk 但块太长」不是一件事；借它会丢掉可读的差异，而差异正是用户要看的东西。

**只在应用层加错误边界，不切块。** 否决：错误边界只把空白换成说明，那个文件仍然看不了，而用户要的就是它。反过来只切块也不要：块被切到上限内仍可能在别处抛错，整页类型退役的代价太大。

**依赖宿主错误边界的 `abdicate` 行为。** 否决：那是宿主的页类型生命周期，不是本插件能约定的契约；正文的失败必须在本插件里收住。

## Consequences

超大文件的差异重新可见，整页类型不再因单文件渲染失败而退役。代价是超限文件在差异正文里表现为多个相邻的文件段头（每块一个），分段暂存轨道因此会在同一个文件上出现多组按钮——它们各自对应切片后的块，行号仍指向原文件。

切块上限取 4000：远低于实测触发的 12.5 万，又高于 forge 变更视图自己的 `LARGE_FILE_LINES`（1000，超过即折叠成一个展开条），因此正常文件不会被切。

## Verification

`test/hunk-chunking.test.mjs` 覆盖切分的行号连续性、两侧行号一致性、标记行归属与上限边界；`test/forge-adapter.test.mjs` 断言 12000 行的块经 `toForgeHunks` 后每块不超上限且末行号不偏移。移除切分会让后一条断言变红，据此确认它盯住了这个行为。
