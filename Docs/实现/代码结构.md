## 数据源

文案与操作元数据以 JSON 为唯一数据源，由薄层直接读入（`import … with { type: 'json' }`，两端构建都原生支持；宿主 tsc 会把 JSON 一并产出到 `lib/`）：

| 数据源 | 薄层 | 内容 |
|---|---|---|
| `panel/menu-actions.json` | `panel/menu-actions.ts` | 图形区右键操作的 id、引用类型、菜单名称 |
| `panel/change-menu-actions.json` | `panel/change-menu-actions.ts` | 变更区右键操作的 id、适用目标、分组、菜单名称 |
| `source-control/ai-commit-prompts.json` | `source-control/ai-commit-prompts.ts` | AI 提交提示词 |

两份菜单都按「JSON 给元数据与名称 + 代码按 id 绑处理函数」组织：新增操作 = JSON 加一条 + 在对应注册表里补一个同 id 的处理函数。变更区三个目标（文件夹行 / 文件行 / 分组标题）共用 `panel/change-menu.ts` 的注册表，操作声明适用的 `targets`，因此不会出现「某个目标漏了某项操作」。

JSON 在 TS 里是宽类型（字符串推成 `string`、缺键不报错），因此形状、占位符与各目标的必备操作由 `test/data-sources.test.mjs` 校验。

## 宿主侧数据层

宿主侧数据层分四块。`working-tree.ts` 是 git 执行层与工作区变更的对外出口（只做再导出，实现见 `git-exec.ts` 执行层、`status-parse.ts` 状态解析、`worktree-ops.ts` 读取与暂存提交、`discard.ts` 丢弃、`worktree-remove.ts` 移除工作树、`submodule-ops.ts` 子模块），其 `parseStatusSnapshot` 解析 `status --porcelain=v2 --branch`（条目与分支上游来自同一次调用，v2 的 `.` 空列按空列输出）。

`git-parse.ts` 是纯解析层，输入 git 原始输出、输出数据结构，无 git 调用，可被测试直接导入，分支同步解析见其 `BRANCH_SYNC_FORMAT` 与 `parseBranchSync`。

`git-query.ts` 是只读查询层（`getWorkingTreeSnapshot` 是快照命令的实现，其合并判定读 git 目录下的 `MERGE_HEAD` 文件，不起子进程）；`git-actions.ts` 是操作层，两者都返回 `ErrorInfo`（成功 `null`）。

`runGit` 不设超时（原因见[提交框](../功能/提交框.md)）。执行层只登记在跑的子进程，用于宿主退出与终止信号时按进程树清理（`killRunningGit`）。

非只读命令结束时按 `onRepositoryWrite` 通知一次（判据是命令跑完，不看退出码：冲突合并、拣选冲突与变基停下都以非零退出但已改动仓库），宿主据此按仓库作废快照、提交图与仓库信息缓存（含祖先与后代，以及共享同一 git 公共目录的其它工作树）、作废发现缓存并广播 `repository-write`。

`runGit` 的只读结果缓存按毫秒计有效期，只对**输出不随工作区或索引当前内容变化**的子命令（`log`、`show`、`for-each-ref`、`rev-list` 等）生效。`status`、`diff`、`ls-files` 的输出随工作区与索引变化，而缓存失效只覆盖插件自己执行的写命令 —— 插件之外的写（编辑器、外部命令）无从感知，子模块的内部改动更会改变**父仓库** `status` 的结果（父仓库把子模块的内部改动记成自身的一条条目），因此这三类命令一律现读现用，不进结果缓存。

子进程环境由 `gitEnvironment(readOnly)` 生成：`LANGUAGE` / `LC_ALL` / `LANG` 固定为英文（失败归类与部分解析依赖英文措辞，父进程已显式给出时保留用户取值）；`GIT_OPTIONAL_LOCKS=0` 只加在只读命令上，写命令不设，否则索引可能不落盘。

`commitStaged` 的提交信息为空串时用 `git commit --no-edit`（沿用 `MERGE_MSG`）。

`discardPaths` 按索引模式 `160000`（`git ls-files -s` 判定，解析在 `git-parse.ts` 的 `parseIndexEntries`）区分子模块条目：子模块走 `checkout --detach` 而非 `git restore`，未跟踪路径用 `git clean -f`（不加 `-ff`/`-d`）。三种子模块结局与未删除的独立仓库如何回报给用户，见[功能说明](../功能/功能说明.md)。

`ignore.ts` 写入忽略规则（最近的 `.gitignore` 与本地排除文件），规则写法与去重是纯函数，放在 `ignore-rules.ts`；本地排除文件在 `.git` 目录内，客户端以宿主返回的绝对路径按普通文件打开。

克隆命令由 `git/clone-command.ts` 构造（`shallowCloneArgs` 生成浅克隆参数）、`git/terminal-run.ts` 在 DSH 终端页执行，流程与参数见[克隆](../功能/克隆.md)。

浅克隆的判定在 `worktree-branches.ts` 的 `isShallowClone`：读公共目录下的 `shallow` 文件，链接工作树与子模块因此共用所属仓库的这一份。仓库节点把它带成 `shallowClone` 字段（宿主 `repo-node.ts` 与客户端 `shared/types.ts` 同形）。恢复由 `git-actions.ts` 的 `restoreFullHistory` 完成，路由命令是 `unshallow`：先按远程还原 refspec 与 `remote.<name>.tagopt`，再按需执行 `fetch --unshallow`，一次补完所有远程共用的历史。

## git 钩子

`hooks.ts` 探测（纯文件系统，不调 git；判据与 60 秒缓存见[提交框](../功能/提交框.md)），客户端换仓库时探测一次。取消勾选经 `skipHooks` 让 `commitStaged` / `pushUpstream` / `pushBranch` 追加 `--no-verify`。

## AI 提交信息

改动收集在 `commit-diff.ts`（二进制只留文件名、文档排在代码之后、合并提交取被合并入的提交），请求组装在 `ai-commit-request.ts`。行为见[AI 提交信息](../功能/AI提交信息.md)。

## 数据形状与分隔符

未合并条目的两列组合与文案只在 `shared/conflict-kind.ts` 定义一份，宿主据此给 `WorkingTreeEntry` 补 `unmerged`，客户端分组与差异页读同一份。`fileDiffContent` 命中冲突时改按阶段取源，并回投 `conflict`、`conflictKind` 与 `conflictStages`。

合并视图不解析冲突标记：三方文本各自与基线算行差异，再按基线位置对齐成区间（改到同一处即同一区间）。区间与选择表在 `shared/merge-ranges.ts`，写回时才由 `merge-ops.ts` 算出全文。分段暂存另用一套切分：`patch-hunks.ts` 切成 `@@` 块后交回 `git apply --cached`，取消暂存加 `-R`。

数据形状集中在 `git-types.ts`，其字段名即前端契约。多记录命令一律用 `-z` 取 NUL 分隔输出，记录内字段用 `%x00` 分隔；**`for-each-ref` 的转义是 `%00`**，写成 `%x00` 不会被展开，分支同步的格式串 `BRANCH_SYNC_FORMAT` 同样用 `%00`。`git diff-tree -z` 的输出以提交对象名开头，解析时须跳过（`skipLeadingObjectName`）。

## GitHub 集成

`gh-cli.ts` 是 GitHub 集成层：以数组参数直接 spawn `gh`（不经 shell），设 `GH_PROMPT_DISABLED=1` 避免等待交互输入。`classifyGhFailure` 把输出归类为 missing-cli / not-logged-in / missing-scope / forbidden / not-found / invalid / unknown，前端据此降级；GitHub 对无权资源回 404，建仓库场景归入无权限。入口与降级行为见[远程与 SSH](../功能/远程与SSH.md)。

## 客户端分层

`src/client/panel/index.ts` 持有状态，分区组件只接收已算好的数据与回调；纯计算抽成无 React 依赖的模块以便直接单测。客户端不得反向依赖 `index.ts`（会成环），共享的图标等放在独立模块。

## 打开文件与差异

差异页实现在 `client/diff/`：`forge-adapter.tsx` 把宿主算出的 `FileDiffContent` 映射成 DSH forge 变更视图 `DiffFile` 的入参，`forge-locales.ts` 绑它的文案字典，`resource-path.ts` 管地址换算。普通文件与差异一律经 `tabActions.openResource(dsh-resource://file/…)` 交宿主认领，行为见[功能说明](../功能/功能说明.md)。

`DiffFile` 按源码导入，视图实现与 DSH 面板共用一份，构建约束见[构建与测试](构建与测试.md)。它是「变更视图里的一个文件段」，适配层按单文件页取舍：跨文件菜单不渲染，已审阅复选框仅占位并由样式隐藏。

行评论接通为对话引用：在差异上按下并拖过若干行即可选区，forge 的评论框（`ReviewComposer`，界面全部来自库）随后打开，确认后把「文件、版本、行号区间」随正文插进当前会话输入框（`inputActions.insertQuote`）。

界面不复刻，只有手势由本插件接管：forge 的行选取只认 hunk 内的行（行号是否可点、区间是否成立都查 `file.hunks`），折叠区展开后的未变更行选不中，跨 hunk 的区间会被整段拒绝。`line-range.ts` 改从渲染出的行读行号，因此两者都能连成一片；`DiffFile` 不再收到 `review`，避免两套手势抢指针。
