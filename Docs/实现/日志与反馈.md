# 日志与反馈

本文是文本日志、耗时汇总与反馈提交的参考页。功能入口见[功能说明](../功能/功能说明.md)。

## 目录与命名

| 层级 | 名称 | 说明 |
|---|---|---|
| 根目录 | `$DSH_HOME/dsh-source-control/logs/` | 与插件状态文档同级；`DSH_SOURCE_CONTROL_HOME` 可改根目录 |
| 日文件夹 | `YYYY-MM-DD` | 按本地日期归档 |
| 日志文件 | `logcat-YYYYMMDD-HHmmssSSS-<pid>.log` | 每次启动一个文件；文件名升序即启动先后 |

## 模块划分

日志模块三件：`log-format.ts` 只做格式（logcat threadtime：`MM-DD HH:MM:SS.mmm  PID  TID LEVEL TAG: message`，含换行的消息逐行写出、续行沿用同一时间戳）；`log-retention.ts` 只做命名与淘汰判据（纯函数，可直接单测）；`logger.ts` 负责落盘与清理。

目录为 `<root>/<YYYY-MM-DD>/<YYYYMMDD>-<HHmmss>.log`，root 与 `state-store.ts` 同序解析（`DSH_SOURCE_CONTROL_HOME` → `DSH_HOME` → `~/.dsh`）。文件名含启动时刻，因此同一日文件夹内按文件名升序即启动先后（同一秒内多次启动时追加写入同一份）。

写入策略：行先入缓冲，`FLUSH_DELAY_MS`（250ms）合并为一次追加写，缓冲到 512 行立即落盘，`process.on('exit')` 同步收尾。定时器 `unref()`，不阻止进程退出；写盘失败静默，不影响插件功能。

## 耗时汇总

耗时汇总（`api/cost.ts`）：单条命令不记日志，按「一次刷新」把墙钟、命令耗时合计、git 子进程数与各命令明细汇总成一行 `perf` 记录。

分组按客户端随请求带来的 `refreshId`（`panel/graph-window-cache.ts` 的 `nextRefreshId`，带随机会话前缀以免多面板撞号），无编号的命令按仓库与空闲窗口（3 秒）归组；**只按空闲定时器冲刷**，不因同一仓库出现新编号提前写出 —— 一轮里的提交图与工作区快照并行发出、下一轮可能在上一轮收尾前就开始，编号交错到达会让每条汇总只剩部分命令。墙钟取「首条命令开始 → 末条命令结束」（不含命令之间的空闲），子进程数按仓库分别计数。

## 清理

`initLog()` 调 `cleanLogs()` 各判一次。保留期按日文件夹名比字符串（`planExpiredDayFolders`，当天算第一天，早于「今天 − 14 天」的整体删除）；体积按 `planDayEvictions` 从最新文件向前累计到 `DAY_FOLDER_LIMIT_BYTES`（15 MB），超出部分进入淘汰名单；**正在写入的那一份由 `keep` 排除**，既不参与累计也不会被删。

## 反馈

`feedback.ts` 是提交编排（取日志 → 脱敏 → 打包 → `gh issue create --body-file` → 回投 issue 地址），`feedback-text.ts` 拼正文（纯函数），`log-archive.ts` 用系统 `tar -a -cf` 打包（tar 不可用时退回未压缩副本），`log-redact.ts` 脱敏（纯函数）。

脱敏只在提交反馈时生效，磁盘上的原始日志保持原样；本地路径**不处理**，只替换 URL 账号口令、令牌串与独立出现的系统用户名，占位符分别是 `<url-credential>` / `<token>` / `<user>`。正文改走 `--body-file`：长描述与日志说明会让命令行参数超出系统上限。

反馈入口有两处，打开同一个页签：设置面板顶部的「反馈」页签，以及存储库区标题行里克隆与设置按钮之间的反馈按钮。

字段：类型（缺陷 / 建议 / 其它，写进 issue 标题前缀）、标题、描述。勾选「附带日志文件」后，宿主取当前启动的日志、按需脱敏、压成 zip，放在日志根目录的 `outbox/` 下。点「提交反馈」由宿主执行 `gh issue create --repo xzy-nine/dsh-source-control --title … --body-file …`；提交成功后自动在新标签页打开该 issue。

脱敏（默认开启，可勾选「停用脱敏」）：

| 内容 | 占位符 |
|---|---|
| URL 里的账号口令 | `<url-credential>` |
| 令牌串（`ghp_` / `github_pat_` / `sk-` / `xox[baprs]-` / `Bearer`） | `<token>` |
| 系统用户名（独立出现时） | `<user>` |

本地路径不处理：排查问题需要看清文件位置，路径里的用户名因与分隔符相邻也按路径成分保留。「豁免字符串」按行登记需要原样保留的内容，登记后不再替换。

未安装 `gh`、未登录、缺 scope 或没有该仓库的 issue 权限时，弹窗给出对应处理建议与日志目录，由用户自行安装 / 登录 / 补授权，或直接到上游仓库手动创建 issue 并上传压缩包。

日志不交给 `gh issue create --attach` 上传：该接口的 user-attachments 端点只接受图片与视频的 content type，文本与压缩包一律被 `content_type` 校验拒绝（实测 `.log`/`.txt`/`.zip`/`.pdf` 均失败）。因此流程是「本地打包 → 建 issue → 打开 issue 提示用户把压缩包拖进评论框」。
