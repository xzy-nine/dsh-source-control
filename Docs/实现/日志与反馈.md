# 日志与反馈

本文是文本日志、耗时汇总与反馈提交的参考页。功能入口见[功能说明](../功能/功能说明.md)。

## 目录与命名

| 层级 | 名称 | 说明 |
|---|---|---|
| 根目录 | `$DSH_HOME/dsh-source-control/logs/` | 与插件状态文档同级；`DSH_SOURCE_CONTROL_HOME` 可改根目录 |
| 反馈暂存 | `outbox/` | `--body-file` 的载体，即写即删；启动时整目录清空 |
| 日文件夹 | `YYYY-MM-DD` | 按本地日期归档 |
| 日志文件 | `YYYYMMDD-HHmmss.log` | 每次启动一个文件，写满上限时另起一份；文件名升序即先后 |

## 模块划分

日志模块三件：`log-format.ts` 只做格式（logcat threadtime：`MM-DD HH:MM:SS.mmm  PID  TID LEVEL TAG: message`，含换行的消息逐行写出）；`log-retention.ts` 只做命名与淘汰判据；`logger.ts` 负责落盘与清理。

root 与 `state-store.ts` 同序解析。

写入策略：行先入缓冲，`FLUSH_DELAY_MS`（250ms）合并为一次追加写，缓冲到 512 行立即落盘，`process.on('exit')` 同步收尾。定时器 `unref()`；写盘失败静默。

**单份文件按字符分片**：新增记录会越过 `LOG_FILE_CHAR_LIMIT`（60000）时闭合当前文件、另起一份，不丢弃记录；两侧各写一行分片标记，单独拿到一份也看得出记录续到别处。上限来自评论正文的 65536 字符，留约 5500 字符给评论包装。同一秒内写满时顺延一秒，避免与旧文件同名而写回旧文件。

## 耗时汇总

耗时汇总（`api/cost.ts`）：单条命令不记日志，按「一次刷新」把墙钟、耗时合计、子进程数与命令明细汇总成一行 `perf`。

分组按客户端随请求带来的 `refreshId`（`panel/graph-window-cache.ts` 的 `nextRefreshId`，带随机会话前缀以免多面板撞号），无编号的命令按仓库与空闲窗口（3 秒）归组；**只按空闲定时器冲刷**，不因同一仓库出现新编号提前写出 —— 一轮里的提交图与工作区快照并行发出、下一轮可能在上一轮收尾前就开始，编号交错到达会让每条汇总只剩部分命令。墙钟取「首条命令开始 → 末条命令结束」（不含命令之间的空闲）。

子进程数按「命令自己的轮次登记」统计：`routes.ts` 为每条命令建一个 `api/refresh-scope.ts` 的登记并用 `runInRefreshScope` 包住处理体，`spawnGit` 每启动一个子进程就把当前登记的计数加一，汇总累加该轮各命令的计数。按仓库取计数器再算差值不成立：并发轮次的时间窗重叠时会互相把对方的子进程算进来，而单命令轮次在收尾后才取基线，差值恒为零。

## 清理

`initLog()` 调 `cleanLogs()`。保留期按日文件夹名比字符串（`planExpiredDayFolders`，当天算第一天）；体积按 `planDayEvictions` 从最新文件向前累计到 `DAY_FOLDER_LIMIT_BYTES`（15 MB）；**正在写入的那一份由 `keep` 排除**，不参与累计也不会被删。

`cleanLogs()` 同时清空 `outbox/`：里面只有 `--body-file` 的载体文件，内容都已进了 issue；载体即写即删，中途失败留下的由下次启动清掉。

## 反馈

`feedback.ts` 是提交编排（取日志 → 脱敏 → `gh issue create --body-file` → 按上限合并日志 → `gh issue comment --body-file`），`feedback-text.ts` 拼主正文（纯函数），`feedback-comment.ts` 合并评论正文（纯函数），`log-redact.ts` 脱敏（纯函数）。

脱敏只在提交反馈时生效，原始日志保持原样。正文走 `--body-file`：长描述会超出命令行参数上限。

反馈入口有两处，打开同一个页签：设置面板的「反馈」页签，与存储库区标题行里克隆和设置按钮之间的反馈按钮。

字段：类型（缺陷 / 建议 / 其它，写进 issue 标题前缀）、标题、描述。勾选「附带日志文件」后另有「日志范围」（1 / 3 / 5 / 15 天，只在本页有效，默认 1 天）与「日志位置」列表——列表默认折叠。点「提交反馈」由宿主执行 `gh issue create --repo xzy-nine/dsh-source-control --title … --body-file …`，成功后逐条追加日志评论。

结果弹窗说明日志分成了几条评论（或有哪条发送失败），issue 地址可点，另带「自动打开反馈页便于查看」（默认勾选）。

脱敏（默认开启，可勾选「停用脱敏」）：

| 内容 | 占位符 |
|---|---|
| URL 里的账号口令 | `<url-credential>` |
| 令牌串（`ghp_` / `github_pat_` / `sk-` / `xox[baprs]-` / `Bearer`） | `<token>` |
| 系统用户名（独立出现时） | `<user>` |

本地路径不处理：排查问题需要看清文件位置。「豁免字符串」按行登记原样保留的内容，登记后不再替换。

未安装 `gh`、未登录、缺 scope 或没有该仓库的 issue 权限时，弹窗给出处理建议与日志目录，由用户自行补齐，或到上游仓库手动创建 issue。issue 已建成、日志评论发送失败时只回报失败原因，不重开一条 issue。

日志走**评论正文**而不是附件：`gh issue create --attach` 的 user-attachments 端点只接受图片与视频的 content type，文本一律被拒绝（`.log`/`.txt`/`.zip`/`.pdf` 均实测失败）。评论侧只做**合并、不拆分**——一份日志整份落在某一条评论里，装不下就留给下一条。每条评论的日志包在 `<details>` 里，点开才展开。早于落盘上限的历史文件会独占一条并截断，说明里给出本地路径。
