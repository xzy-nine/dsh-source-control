# 显示与状态

本文是界面渲染、忙碌状态与状态持久化的参考页。功能行为见[功能说明](../功能/功能说明.md)，性能见[性能与缓存](性能与缓存.md)。

## 显示到界面

「数据已到手 → 界面呈现」这一段只做必要工作：状态按帧步进、派生值按引用记忆化、缓存有容量上限。

| 机制 | 落点 | 约束 |
|---|---|---|
| 窗口状态按起始行步进 | `graph/use-graph-windowing.ts` 的 `topIndex` 与 `graph/window-range.ts` | 滚动事件经 `requestAnimationFrame` 合并（缺失时退回 `setTimeout(0)`），起始行未变不写状态；行偏移或可视高度变化后按当前滚动位置重算 |
| 行级 `memo` | `graph/index.ts` 的 `LaneCell`/`RefChip`/`IndicatorRow`/`DetailGutter`/`CommitRow`/`CommitGraph`、`changes.ts` 的 `ChangeNodeRow`/`CommitDetail`/`ChangeGroup`、`sections/` 下三个分区与 `CommitBox`/`ChangeLists`、`repo-row.ts` 的 `RepoRow` | 传进去的回调必须是 `useCallback` 或模块级稳定值；行组件按「哈希 + 文本」这类稳定参数自建闭包 |
| 提交框与变更列表分拆 | `sections/changes.ts` 的 `CommitBox` 与 `ChangeLists` | 输入提交信息只重渲染提交框；同文件内 `css.commitBox` 须排在 `css.changesScroll` 之前，两个分组的 `staged: true`/`staged: false` 须排在其后（`primitives.test.mjs` 按文本顺序断言） |
| 派生值按身份缓存 | `graph/row-model.ts` 的 `titleOf`/`labelsOf`、`panel/changes.ts` 的 `guidesOf` | `labelsOf` 的缓存键含 HEAD，检出后自动重算 |
| 派生值按键缓存 | `graph/row-model.ts` 的 `avatarUrlsOf`、`panel/language.ts` 的 `needsTranslationMemo` | 上限各 1024，键含语言或边长 |
| 悬停缓存容量 | `panel/use-commit-stats.ts` 的 `statsByHash`/`messageByHash`/`translatedByHash`/`translatedFromByHash` | 各自独立上限 1200，写入后按插入序淘汰；与既有 TTL 清理正交 |
| 对象身份复用 | `panel/commit-diff.ts` 的 `mergeCommits`/`mergeEntries` | 判据复用 `commitsEqual`/`entriesEqual`（提交只比影响图形的字段）；顺序取新列表，**总是返回新数组**，`full` 刷新不短路 |
| 时钟门控 | `panel/use-panel-layout.ts` 的 `refreshClock` | 只按 `document.visibilityState === 'visible'` 推进；`visibilitychange` 时启停并立即推进一次 |

`src/client/shared/cache.ts` 是这些缓存的基元（`LruMap`/`forObject`/`forKey`/`mapsEqual`/`trimOldest`），纯模块无 React 依赖。新增缓存先在此取基元，不另写淘汰逻辑。

列表替换后未变化的元素保持对象身份（`mergeCommits`/`mergeEntries`），下游按 `commits`/`entries` 引用记忆化的泳道布局与变更树因此不重算。

## 忙碌状态

进行中的操作按「仓库路径 + 影响面」记录在面板状态里（形状见 `types.ts` 的 `BusyEntry`，判据在 `panel/busy.ts`，可直接单测）。影响面四档，互不阻塞：

| 影响面 | 覆盖 | 禁用的控件 |
|---|---|---|
| `read` | 只读或只导出、不改动仓库的操作：提交图、工作区、差异内容、归档导出 | 目标仓库的刷新入口 |
| `commit` | 暂存、取消暂存、丢弃、忽略规则、贮藏、提交 | 更改区与提交框 |
| `history` | 检出、合并、变基、重置、拣选、分支/标签/远程配置 | 图形区与仓库行的操作 |
| `network` | 抓取、推送、拉取、发布、创建 Pull Request、gh 查询 | 目标仓库的抓取/推送/发布/同步 |

同一仓库的同类操作可并存多份记录，逐个移除；仓库行右键菜单按该行仓库判定，别的仓库在忙不影响它。打开文件、打开设置这类只读入口不因任何影响面禁用。宿主侧不串行化命令：每条请求独立执行，面板的阻塞只来自上述控件禁用。

后台读取只被前三档挡住：`panel/busy.ts` 的 `isReadBlocked` 把 `network` 排除在外。推送与抓取不改写本地对象库与工作区，让它们挡住读取会让两个分区在一次推送的整段时间里停更；宿主侧同一判据是 `git-exec.ts` 的 `whenLocalSettled`，门控细节见[性能与缓存](性能与缓存.md)。

## 状态持久化的分级

分三级，判据只有一条：该状态是否值得跨会话保留。**持久化一律落宿主**，浏览器端只承担会话级 —— 换浏览器、换标签页、清缓存都不会丢；窗口级只活在本次挂载里，会话级关标签页即清。

| 级别 | 载体 | 存活范围 | 适用 |
|---|---|---|---|
| 窗口级 | 组件 `useState` / `useRef` | 本次挂载 | 瞬时交互与派生数据：分组折叠集合、过滤弹窗的选中与搜索、`amend`、`runHooks`（本次提交与推送是否运行 git 钩子，不持久化，提交/推送完成与换仓库时复位）、`maxCommits`、分页与请求中标志 |
| 会话级 | 浏览器 `sessionStorage`（客户端经 `panel/storage.ts` 的 `loadSessionValue` / `saveSessionValue` 读写） | 本次会话，关标签页即清 | 与具体仓库绑定、重填成本高的输入：提交信息草稿（键 `ggg-commit-msg:<仓库根绝对路径>`） |
| 持久化 | `$DSH_HOME/dsh-source-control/state.json`（宿主侧 `source-control/state-store.ts`，客户端经 `panel/storage.ts` 的内存镜像读写） | 跨浏览器、标签页与重启 | 用户偏好与布局（设置项、分区高度与展开态、仓库树展开与选中）、引用筛选（单键 `dsh-source-control-ref-filter` 内按规范化仓库路径分列：`'all'` 或引用 id 数组；默认「自动」不落盘，与 VS Code 图形视图一致）、工作区仓库位置缓存 |

客户端不直接读写 `localStorage` / `sessionStorage`：`panel/storage.ts` 是唯一出口，宿主侧在首屏预取一次到内存镜像，读走镜像（同步，供 `useState` 初始化），写更新镜像并异步落盘。仓库位置缓存在 `state.json` 的 `repos` 段按工作区路径分列，键值对在 `entries` 段。旧版本浏览器里的数据由 `api/state.ts` 的 `migrateLegacyState` 在首次进入时搬一次并清掉旧键。

新状态先在此表定位：窗口级留组件状态；只值得活一次会话、且与具体仓库绑定的输入（如提交信息草稿）落会话级；其余一律落宿主。不要用 `localStorage`。
