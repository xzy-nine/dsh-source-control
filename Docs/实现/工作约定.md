# 工作约定

本文是仓库级工程约定：文档分层、测试边界、语言与协作要求。散文与注释的写作规则归[散文标准](../../.agents/skills/source-control-prose-standard/SKILL.md)，推理记录泄漏的排查归 [source-control-trim-cot-leakage](../../.agents/skills/source-control-trim-cot-leakage/SKILL.md)，文档层级与预算归[文档标准](../AGENTS.md)。本节不重复它们的规则。

## 文档分层

- [README](../../README.md) / [README.en.md](../../README.en.md) 只概述整体能力与特色功能，不列细节。
- 每一项功能的完整行为写在[功能说明](../功能/功能说明.md)及其子页。
- 代码结构、构建、测试与性能等实现内容写在 `docs/` 的实现页。
- 影响长期维护的判断写入 [Agent Note](../../.agents/notes/README.md)；纯机械改动与局部界面调整豁免。

## 测试边界

- **测试不测界面文案**：断言标识符、结构或行为，不断言菜单项、按钮等展示字符串；文案归各模块导出的常量。
- **不写一次性改动的一次性测试**：局部、机械、只影响单个界面的改动不补测试。
- **并发前提是还原进程级状态**：用例改动 `globalThis`、`process.env` 或真实句柄后必须还原，见[执行拓扑](构建与测试.md#执行拓扑)。

## 工程约束

- **规则必须可执行。** 新增一条被评审强制的规则时，同时给出它能变红的门禁；只靠人记的规则会被忘掉。
- **改代码就改它拥有的文档。** 配置、默认值、错误、对外行为在同一变更里更新对应 README 与 JSDoc。
- **共享状态必须有归属者。** 模块级缓存、单例、全局注册表都要挂到服务、实例或显式作用域上。
- **能复用 DSH 已导出的能力就直接用，不自行重造**。
- **复制第三方代码时先用命令复制再改**，不得凭记忆重写；同时标明来源与许可。
- 沙箱报错时先提权重试一次（仅在沙箱状态下）。

## 语言

回复与面向用户的文本用中文；代码、命令、路径、标识符与逐字引用的外部文本保持原样。
