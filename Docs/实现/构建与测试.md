# 构建与测试

本文是构建、静态检查、提交钩子与测试的参考页。代码结构见[代码结构](代码结构.md)。

## 构建

```bash
pnpm install
pnpm lint               # oxlint --type-aware src（规则集见 .oxlintrc.json）
pnpm lint:fix           # 同上，能自动修的（花括号、可选链）就地改
pnpm build              # build:host（tsc → lib/）+ build:client（esbuild → lib/client.js）
pnpm typecheck          # 宿主（tsconfig.json）与客户端（tsconfig.client.json）两段
pnpm check:duplication  # jscpd 扫描 src/，出现基线之外的重复即失败（3 行 / 20 token）
pnpm check:comment-prose # 扫描 src/ 注释，出现基线之外的解释性注释即失败
pnpm test               # pretest 先跑完整 build 与两道门禁，再 node --test test/*/*.test.mjs
```

## 门禁基线

各门禁的存量记录统一放 `baselines/`：`duplication-baseline.json`（重复代码）、`comment-prose-baseline.json`（解释性注释）。脚本只从该目录读写。

## 重复代码门禁

`scripts/check-duplication.mjs` 用 jscpd 扫 `src/`，与 `baselines/duplication-baseline.json` 里的指纹逐条比对；出现基线之外的克隆即以退出码 1 失败。阈值取 3 行 / 20 token：宁可基线多记几处短重复，也不放过换个名字重抄的同一段逻辑。指纹由「文件对 + 片段行数 + 片段内容摘要」构成，不含行号，摘要按归一化行尾计算：无关改动与检出时的换行风格差异都不会让基线失效，同文件对、同长度但片段内容被替换则算新的重复。比对按出现次数进行，当前次数超出基线次数才算新增（jscpd 会把一处重复按相邻窗口合并成多条克隆）。片段行数取两侧行数的较小值，两侧各自取绝对值：jscpd 合并相邻窗口给出一侧起止行反向的区间，其 `end - start + 1` 为负数。指纹行数落在 1–16。

基线只允许调低；无法消除的（如跨构建目标的类型镜像）才用 `--update` 调高并说明理由。门禁挂在 `pretest` 上。

指纹算法改变时 `--update` 整体重写基线，条数随之升降；提交信息写明改变的算法。

## 构建约束

- 数据源是 JSON，两端都直接 import（`resolveJsonModule` 已开启，宿主侧按 `type: 'json'` 导入属性读写）。JSON 随 `tsc` 产出到 `lib/`，esbuild 把它内联进客户端包，运行时不额外请求。`lib/` 只含构建产物，`src/` 里不出现生成文件。
- 客户端外部化模块取 DSH 的 `PLATFORM_MODULES`；浏览器模块表的 seed 只含这些，请求表外的包运行时抛错，其余依赖打进包内。
- `dsh.client.inject` 只列客户端**模块包名**（宿主按此先装载对应模块工厂），不列 cordis 服务名；服务依赖由入口导出的 `inject` 声明。
- `jsx: 'automatic'`；`charset: 'utf8'`（保留中文字面量）。
- 客户端类型检查经 `tsconfig.client.json` 的 `paths` 用 forge 发布的 `lib/types/**/*.d.ts`，esbuild 仍打包真实源码。
- CSS 模块用 esbuild 的 `local-css` loader，**必须配 `outdir`**，否则报 `Cannot import ... without an output path configured`。`local-css` 只产类名映射，样式文本需脚本单独收集并内联为 `<style id="dsh-source-control-module-style">`，`lib/` 下不留 CSS 文件。
- CSS 模块按组件拆分，**作用域前缀按文件生成**：同一条选择器里的多个类名必须定义在同一文件，否则两侧前缀不同、复合选择器失效。跨组件的共享类放 `css/shared.module.css`；由 JS 动态切换、且要加在不同模块元素上的状态类（`menuTarget`）在样式里写 `:global(...)`，名字集中在 `css/state-classes.ts`，样式与组件共用同一份。
- `assets/icons/` 的 SVG 以文本内联，运行时不请求额外资源。
- `lib/` 是构建产物，不提交（`.gitignore`）；发布内容由 `package.json` 的 `files` 白名单决定。

## 版本声明

DSH 兼容性只看顶层 `engines.dsh`（DSH 用 `includePrerelease` 求值，上界写到当前已发布的最高版本，如 `<=0.2.2-rc.5`）；声明了 `engines.dsh` 时 DSH 忽略 `peerDependencies` 里的 `@deepseek-ai/dsh-*` 范围，因此不逐版本维护列举式列表。`peerDependencies` 只声明宿主提供的模块（其**名字**供 profile 解析按宿主实例共享），区间与 `engines.dsh` 对齐；cordis 与客户端组件库的 `devDependencies` 固定为构建与测试所针对的精确版本。`zod` 跟随 `@deepseek-ai/dsh-storage-domain` 的版本：`defineDomain` 要求两侧共用同一份 zod。

## 静态检查

规则集是仓库根的 `.oxlintrc.json`，对齐 DSH 主仓的严格档：正确性、可维护性与类型感知规则全开（`typescript/*` 的 type-aware 规则 + `eslint-plugin-sonarjs`）。**不启用 `@stylistic` 风格规则**：本仓库用 Tab 缩进与分号，与主仓的 2 空格、无分号相反，照搬会产生上万条纯排版告警。

`oxlint --type-aware` 的类型信息由 `tsconfig.json` / `tsconfig.client.json` 提供，因此两处约束不可省：

- 宿主 `tsconfig.json` 必须保留 `"types": ["node"]`。缺它时 tsgolint 解析不到 Node 全局类型，会把 `process`、`setInterval` 判成 `error` 类型，凭空报出数百条 `no-unsafe-*`（`tsc` 因默认加载 `@types/*` 而不报，两边结论因此不一致）。
- 客户端 `tsconfig.client.json` 是 `strict: false`（既有设计：大量界面代码走 JS 风格），`no-unsafe-*` 系列依赖严格类型信息，故 `.oxlintrc.json` 对 `src/client/**` 单独关闭这五条。

## 注释散文门禁

`pnpm run check:comment-prose` 拦下 `src/` 里可机械识别的解释性注释，分八类：变更叙述、会话与栈范围、评审视角、已死的草稿引用、控制流复述、规划残留、作者口吻、隐喻词。规则与抽取在 [scripts/comment-prose.ts](../../scripts/comment-prose.ts)，注释由 TypeScript 编译器 API 从 AST 取，字符串、模板字面量、正则与 JSX 属性里的定界符不算注释。编辑判断见[散文标准](../../.agents/skills/source-control-prose-standard/SKILL.md)与[精简思维链泄漏](../../.agents/skills/source-control-trim-cot-leakage/SKILL.md)。

规则取宽口径：漏过一处解释性注释无人发现，误伤一处合法注释则会立刻被看到。因此「不再」「旧版」「迁移后」「暂时」「实际上」这类词形一律拦下，由基线或就地标记逐条消化。

规则收录只有解释性读法的词形。指代输入值与位置的词（`原有顺序`、`之前`、`换成`）不在规则范围内。

标准 JSDoc 取值标签（`@param`、`@returns`、`@yields`、`@throws` 及其别名）所在行不做散文判定，其中的 `本次`、`本轮` 指代调用点。其余标签（如 `@example`、`@see`）与标签外的注释照常扫描。

确需保留的注释在行上写 `prose-ok: <理由>`，作用于所在整段注释（相邻 `//` 行或一个块注释）；理由必填，空理由不豁免并报 `marker-without-reason`。

存量记 `baselines/comment-prose-baseline.json`，按「文件 + 规则 + 注释原文」比对而不含行号：无关改动不让基线失效，改写或复制过的注释算新命中。基线只允许调低，调高须用 `--update` 并说明理由。门禁挂在 `pre-commit`（`--staged`）、`pre-push` 与 `pretest` 上。

## 提交钩子

git 钩子由仓库内的 `.githooks/` 承载，`pnpm install` 的 `prepare` 阶段经 `scripts/install-hooks.mjs` 安装，克隆后无需额外步骤。安装只写未设置过的 `core.hooksPath`：已配置成其它值时保留原值并提示，不覆盖（该值可能指向 husky 等工具的钩子目录）。`core.hooksPath` 是相对路径，按各 worktree 根解析，因此主检出与所有 worktree 共用同一份脚本。

| 钩子 | 时机 | 检查内容 |
|---|---|---|
| `pre-commit` | 提交前 | 暂存的 `src/**/*.ts{,x}`（`ACMR`）跑 oxlint 与散文门禁；暂存内容与工作区副本不一致时拒绝；涉及 `Docs/**/*.md` 时跑文档门禁 |
| `pre-push` | 推送前 | `src/` 全量 oxlint + 两段 `tsc --noEmit`；无条件跑散文与文档门禁（推送是最后一道） |

门禁失败时，各脚本经 `scripts/gate-hint.ts` 打印该门禁的规则页路径并要求先读规则再改。

绕过（仅在确有必要时）：`git commit --no-verify` / `git push --no-verify`。

## 测试

**宿主侧测试从 `lib/` 产物导入**（经 `test/lib-import.mjs`）：宿主模块带内部 `.js` 相对导入，由 `src/` 直连 `.ts` 会报 `ERR_MODULE_NOT_FOUND`，故 `pretest` 先构建产物，缺产物即报错，不用 skip 掩盖。**客户端测试从 `src/` 直连 `.ts`**：客户端只有打包后的 `lib/client.js`，取不到内部纯函数。jsdom 与 ui-primitives 类型声明取自 `devDependencies`，装不上即失败。

### 执行拓扑

文件级并行由运行器默认开启，文件内并行默认关闭。哪些文件可并发由测试经 `test/harness.mjs` 声明，不依赖运行器默认值：默认值随 Node 版本与 `--test-isolation` 变化，共享进程级状态的文件被并发即间歇性失败。

- **并发**：不共享进程级可变状态的文件（纯函数、只读源码或 JSON）用 `parallel(name, body)` 把用例登记进并发组；用例之间不得依赖执行顺序，不得共用临时目录、固定端口或未还原的全局桩。
- **串行**：依赖进程级单例（`globalThis` 桩、`process.env`、真实 `fs.watch` 句柄）或起真实 git 子进程的文件，在文件头注明理由并保持串行；单个用例用 `serial(name, fn)` 标注。
- **临时路径与超时**：`tempPath(prefix)` 建进程唯一目录（`join(tmpdir(), '固定名')` 会与兄弟进程撞名）；`--test-timeout=120000` 让挂起的用例在 120 秒后失败并指出用例名。

测试按子系统分在 `test/` 的九个一级子目录（api、repo、git、diff、refresh、state、snapshot、ui、tool），`harness.mjs` 等公共脚本留在根目录；Node 的目录参数不递归，故测试 glob 显式写 `test/*/*.test.mjs`。逐文件的覆盖范围写在各自的测试文件头部注释里。

`api-*` 与 `snapshot*.test.mjs` 从 `lib/` 宿主产物导入，因此 `pretest` 跑完整 `build`。

`primitives.test.mjs` 断言客户端导入的每个 ui-primitives 名字都真实存在：图标导出名带 `Regular` / `Medium` 权重后缀，写成裸名得到 `undefined`，React 只在运行时抛「元素类型无效」并让整页空白。导出名取自 `node_modules` 里固定版本的 `.d.ts`。
