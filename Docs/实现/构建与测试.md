# 构建与测试

本文是构建、静态检查、提交钩子与测试的参考页。代码结构见[代码结构](代码结构.md)。

## 构建

```bash
pnpm install
pnpm lint               # oxlint --type-aware src（规则集见 .oxlintrc.json）
pnpm lint:fix           # 同上，能自动修的（花括号、可选链）就地改
pnpm build              # build:host（tsc → lib/）+ build:client（esbuild → lib/client.js）
pnpm typecheck          # 宿主（tsconfig.json）与客户端（tsconfig.client.json）两段
pnpm check:duplication  # jscpd 扫描 src/，出现基线之外的重复即失败
pnpm test               # pretest 先跑完整 build 与重复门禁，再 node --test test/*.test.mjs
```

## 重复代码门禁

`scripts/check-duplication.mjs` 用 jscpd 扫 `src/`，与 `duplication-baseline.json` 里的指纹逐条比对；出现基线之外的克隆即以退出码 1 失败。指纹由「文件对 + 片段行数 + 片段内容摘要」构成，不含行号，摘要按归一化行尾计算：无关改动与检出时的换行风格差异都不会让基线失效，同文件对、同长度但片段内容被替换则算新的重复。比对按出现次数进行，当前次数超出基线次数才算新增（jscpd 会把一处重复按相邻窗口合并成多条克隆）。

基线只允许调低；确实无法消除的（如跨构建目标的类型镜像）才用 `node scripts/check-duplication.mjs --update` 调高，并在提交信息里说明理由。门禁已挂在 `pretest` 上，`pnpm test` 必然经过它。

## 构建约束

- 数据源是 JSON，两端都直接 import（`resolveJsonModule` 已开启，宿主侧按 `type: 'json'` 导入属性读写）。JSON 随 `tsc` 产出到 `lib/`，esbuild 把它内联进客户端包，运行时不额外请求。`lib/` 只含构建产物，`src/` 里不出现生成文件。
- 客户端外部化模块固定为 `react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@deepseek-ai/dsh-client-ui-primitives`；浏览器半边不得引入其他裸模块。
- `dsh.client.inject` 只列客户端**模块包名**（宿主按此先装载对应模块工厂），不列 cordis 服务名；服务依赖由入口导出的 `inject` 声明。
- `jsx: 'automatic'`（复制的 FileDiff 不显式导入 React）；`charset: 'utf8'`（保留中文字面量）。
- CSS 模块用 esbuild 的 `local-css` loader，**必须配 `outdir`**，否则报 `Cannot import ... without an output path configured`。`local-css` 只产类名映射，样式文本需脚本单独收集并内联为 `<style id="dsh-source-control-module-style">`，`lib/` 下不留 CSS 文件。
- CSS 模块按组件拆分，**作用域前缀按文件生成**：同一条选择器里的多个类名必须定义在同一文件，否则两侧前缀不同、复合选择器失效。跨组件的共享类放 `css/shared.module.css`；由 JS 动态切换、且要加在不同模块元素上的状态类（`menuTarget`）在样式里写 `:global(...)`，名字集中在 `css/state-classes.ts`，样式与组件共用同一份。
- `assets/icons/` 的 SVG 以文本内联，运行时不请求额外资源。
- `lib/` 是构建产物，不提交（`.gitignore`）；发布内容由 `package.json` 的 `files` 白名单决定。

## 版本声明

DSH 兼容性只看顶层 `engines.dsh`（DSH 用 `includePrerelease` 求值，上界写到当前已发布的最高版本，如 `<=0.2.2-alpha.2`）；声明了 `engines.dsh` 时 DSH 忽略 `peerDependencies` 里的 `@deepseek-ai/dsh-*` 范围，因此不逐版本维护列举式列表。`peerDependencies` 只声明宿主提供的模块（其**名字**供 profile 解析按宿主实例共享），区间与 `engines.dsh` 对齐；cordis 与客户端组件库的 `devDependencies` 固定为构建与测试所针对的精确版本。

## 静态检查

规则集是仓库根的 `.oxlintrc.json`，对齐 DSH 主仓的严格档：正确性、可维护性与类型感知规则全开（`typescript/*` 的 type-aware 规则 + `eslint-plugin-sonarjs`）。**不启用 `@stylistic` 风格规则**：本仓库用 Tab 缩进与分号，与主仓的 2 空格、无分号相反，照搬会产生上万条纯排版告警。

`oxlint --type-aware` 的类型信息由 `tsconfig.json` / `tsconfig.client.json` 提供，因此两处约束不可省：

- 宿主 `tsconfig.json` 必须保留 `"types": ["node"]`。缺它时 tsgolint 解析不到 Node 全局类型，会把 `process`、`setInterval` 判成 `error` 类型，凭空报出数百条 `no-unsafe-*`（`tsc` 因默认加载 `@types/*` 而不报，两边结论因此不一致）。
- 客户端 `tsconfig.client.json` 是 `strict: false`（既有设计：大量界面代码走 JS 风格），`no-unsafe-*` 系列依赖严格类型信息，故 `.oxlintrc.json` 对 `src/client/**` 单独关闭这五条。

## 提交钩子

git 钩子由仓库内的 `.githooks/` 承载，`pnpm install` 的 `prepare` 阶段经 `scripts/install-hooks.mjs` 安装，克隆后无需额外步骤。安装只写未设置过的 `core.hooksPath`：已配置成其它值时保留原值并提示，不覆盖（该值可能指向 husky 等工具的钩子目录）。`core.hooksPath` 是相对路径，按各 worktree 根解析，因此主检出与所有 worktree 共用同一份脚本。

| 钩子 | 时机 | 检查内容 |
|---|---|---|
| `pre-commit` | 提交前 | 本次暂存的 `src/**/*.ts{,x}`（`ACMR`）跑 oxlint，反馈快；暂存内容与工作区副本不一致时拒绝提交 |
| `pre-push` | 推送前 | `src/` 全量 oxlint + 两段 `tsc --noEmit`，拦住跨文件类型问题 |

绕过（仅在确有必要时）：`git commit --no-verify` / `git push --no-verify`。

## 测试

**宿主侧测试一律从 `lib/` 产物导入**（经 `test/lib-import.mjs` 的 `importHostModule`）：宿主模块普遍带内部 `.js` 相对导入，由 `src/` 直连 `.ts` 会报 `ERR_MODULE_NOT_FOUND`。因此 `pretest` 必须先把宿主产物构建出来，缺产物即导入失败、测试报错——构建失败本身就是问题，不用 skip 掩盖。

**客户端测试仍从 `src/` 直连 `.ts`**：客户端没有逐模块产物，只有打包后的 `lib/client.js`（ModuleLoader 包络，仅暴露插件入口），无法取到内部纯函数。少数按外部环境跳过的用例（非 git 目录、ui-primitives 源码检出、jsdom 缺失）保留 skip，它们不依赖本仓库构建。
