# AI 提交信息

本文是 AI 生成提交信息的参考页，也是「交给模型什么内容」这条契约的正家。提交框的其他行为见[提交框](提交框.md)。

选择供应商与模型（未配置时回退到当前会话模型），可填写追加到系统提示词末尾的自定义规则；生成时把工作区差异交给所选模型，流式返回并填入提交框。

勾选「修补上一次提交」后，差异改为「上一次提交的改动 + 本次改动」。

生成绑定发起时的仓库，切换仓库、会话或关闭侧栏页都不中断。

## 差异的取回

一次 `git diff --numstat -z -p` 同时取回改动清单与补丁正文：路径取自前者的 numstat 记录，补丁取自同一份输出的后半段。分两次调用会读到两个时刻的工作区。`core.quotePath=false` 让非 ASCII 路径以原文出现。

普通提交取暂存区；暂存区为空时取工作区加未跟踪文件。未跟踪文件不进 `git diff`，按文件内容单独构造补丁。

## 二进制文件只给文件名

二进制判据取 git 自己的结论：`--numstat` 的增删列同时为 `-`。未跟踪文件没有该记录，改按文件头部 8000 字节内是否含 NUL 判定。

二进制内容不进提示词，路径进单独一段清单。纯二进制改动（换图、换资源）因此同样可以生成提交信息，而不是因 diff 为空被拒绝。

## 文档排在代码之后

文档扩展名取 `md` / `markdown` / `txt` / `rst` / `adoc` / `org`，只看文件名的最后一个扩展名，目录名中的点不参与判定。

填充顺序是「代码块按长度升序 → 文档块按长度升序」：预算充足时两者都进，吃紧时先丢文档。单文件截到五万字符，总量上限五十万字符。

## 合并提交先给历史

合并进行中取 `MERGE_HEAD` 指向的提交，该文件每行一个哈希，章鱼合并因此有多行。勾选「修补上一次提交」且该提交本身是合并提交时，取 `rev-list --parents` 得到的第二父提交起。

两者的短哈希与完整信息用一次 `log --no-walk=unsorted -z --format=%h%x00%B` 取回。请求按「被合并入的提交 → 二进制清单 → diff」三段拼接，提示词要求模型先据历史概括合并目的、diff 只补充细节。

## 超长丢弃的告知

因长度上限未进入提示词的文件在提交框告警行列出，同时写进宿主日志。原因分两种：`document` 是文档让位给代码，`budget` 是超出总量上限。列举上限 20 个文件，其余按总数说明。

丢弃清单不写进提示词：模型看不到这些改动的内容，告知它只会诱导它按文件名猜测。
