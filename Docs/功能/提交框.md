# 提交框

本文是提交框行为的参考页。更改区与图形区的其他行为见[功能说明](功能说明.md)。

## 基本信息

- 提交信息支持 Enter 提交、Shift+Enter 换行、Esc 清空草稿。
- 「修补上一次提交」勾选后提交为 `--amend`。勾选期间提交按钮始终可用（只要有提交信息），因此可以在没有暂存改动时只改提交信息；「同步」「发布」在勾选期间让位给提交按钮。
- 提交按钮显示已暂存的文件数量。
- 提交信息可由 AI 生成，见 [AI 提交信息](AI提交信息.md)。

## 合并中

处于未完成的合并（有冲突待解决，或无冲突但尚未提交）时主按钮固定为提交，「同步」「发布」都不出现。此时没有暂存改动也能提交，提交是结束合并的唯一动作；提交信息留空表示沿用 git 生成的合并信息（`--no-verify` 与钩子勾选照常生效），因此信息框为空时提交按钮依旧可用。

## 同步按钮的右键覆盖

同步按钮出现（无暂存改动且相对上游有领先或落后）且本地与上游**各有对方没有的提交**时，在它上面右键给出两种整体覆盖：「用本地覆盖远程（强制推送）」与「用远程覆盖本地（硬重置）」。

前者把当前分支 `--force` 推到上游，后者先抓取再把本地分支 `reset --hard` 到上游。两者都要求先在带勾选的强提醒弹窗里确认，文案写明分别会丢弃多少提交、以及已跟踪文件的未提交改动会一并丢失（未跟踪文件保留）。

## githook

仓库存在可执行的提交钩子（`pre-commit` / `prepare-commit-msg` / `commit-msg`）或推送钩子（`pre-push`）时，提交框左侧出现该勾选项，紧跟在「修补上一次提交」之后，默认勾选。它同时决定提交与推送：取消勾选即本次提交、同步或发布追加 `--no-verify` 跳过钩子；取消状态是临时的，提交或推送完成后与切换仓库时都恢复为勾选，不持久化。位置固定在这里，不随主按钮在提交、同步、发布之间切换而移动。

钩子目录按 git 的规则判定：配置了 `core.hooksPath` 时用它的值（相对路径按工作树根解析，裸仓库按其 git 目录），否则用 git 公共目录下的 `hooks`；链接工作树与子模块共用公共目录下的钩子。Windows 上没有执行位概念，钩子文件存在即视为可执行。

`core.hooksPath` 的取值在宿主缓存 60 秒，钩子文件本身每次现读：增删钩子文件立刻反映，外部改了该配置则最多 60 秒后才反映。

git 命令不设执行时长上限：提交、同步与发布等待钩子自行结束（例如仓库用 Gradle 跑 `ktlintFormat`），插件不因耗时中断它们；远端不可达或凭据缺失时由 git 自身结束进程。

## 右侧入口

提交框右侧的入口（本地排除、翻译、取消合并）各自在条件成立时才出现，按出现顺序从左往右排列，不占固定位置；贮藏始终固定在这排最右端。

## 弹窗里的输入

- 单行输入框：回车即确认，与点确认按钮同义。
- 多行文本域：回车确认，Shift+回车插入换行。
- Esc 或点关闭 / 取消不产生结果。
