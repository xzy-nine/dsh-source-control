# 功能说明

本文件是 dsh-source-control 各项功能的完整行为说明；整体能力概述见 [README.md](../README.md)。

## 自动刷新

面板的数据刷新由四条通道构成，全部可关闭（设置 → 全局设置 → 「文件改动时自动刷新」）：

| 通道 | 触发源 | 节奏 |
|---|---|---|
| 事件驱动 | 当前会话的事件窗口里已落地的写入 / 编辑，且目标在所选仓库内 | 5 秒冷却 |
| 宿主写事件 | 宿主事件流推送的仓库写操作，目标与所选仓库同一 | 5 秒冷却 |
| 兜底轮询 | 定时读取工作区签名，覆盖事件窗口之外的写入（其它会话、编辑器、终端、外部进程） | 页签可见 10 秒 / 不可见 120 秒 |
| 定时抓取 | 定时循环抓取远程引用 | 默认 180 秒 |

### 刷新进行中的界面反馈

后台刷新不阻塞任何控件，界面通过三处指示反映：

- **分区标题栏的状态点**：更改区与图形区各有一个，取数期间为进行中色，空闲为中性色。
- **「上次刷新」相对时间**：紧随状态点，每 30 秒从「刚刚」推进到「n 分钟前」。
- **刷新按钮的呼吸效果**：取数期间图标半透明并呼吸；此时仍可点击，并发刷新由代数判据收敛。

用户主动刷新（点刷新按钮）不走后台登记：它把面板置为加载态，直接呈现占位。

### 刷新结果的告知

后台刷新完成后，若条目数或提交数发生变化，顶部给出一次轻量提示（如「已更新：工作区 3 个改动」）。
计数未变化时不出提示——后台刷新频繁，无变化的刷新不该打扰用户。用户主动刷新被告知省略：
结果就在眼前。

### 兜底轮询的两条路径

轮询读到工作区签名变化后，按 HEAD 是否移动分两条路径：

- **HEAD 移动**（提交、检出、重置）：先请宿主作废缓存，再整轮重载提交图与工作区。
  外部进程的提交不经过本插件的执行层，宿主收不到写事件，缓存不会自动作废。
- **仅文件改动**：只合并工作区快照，不动提交图。一律作废会让每次保存都重取整页提交。

克隆等长时间写盘期间，外层仓库会把正在增长的目录树整体列为未跟踪文件，因此慢档要求
连续两次读到同一份签名才判定变化已停止。

## 刷新相关设置

设置 → 全局设置：

| 设置 | 默认 | 说明 |
|---|---|---|
| 文件改动时自动刷新 | 开 | 事件驱动与宿主写事件两条通道的总开关 |
| 自动抓取远程 | 开 | 定时抓取通道开关 |
| 自动抓取间隔（秒） | 180 | 抓取周期；范围 10–3600 |
| 校对间隔·页签可见（秒） | 10 | 兜底轮询快档；范围 5–600 |
| 校对间隔·页签不可见（秒） | 120 | 兜底轮询慢档；范围 5–600 |
| 提交信息缓存清理（秒） | 300 | 提交统计与完整提交信息的内存保留期；范围 30–3600 |

取值越界时收拢到区间内，不拒绝输入。

## 缓存分层

- **数据缓存**（提交图窗口、仓库信息、工作区快照）只在宿主内存，客户端不自建。
- **渲染态**（面板状态与取数参数）留在客户端，供侧栏页签重新挂载时首帧呈现。
- **提交统计与完整提交信息**按哈希缓存在客户端，按上述清理周期过期；下一次悬停重新按需拉取。

### 缓存失效

| 缓存 | 有效期 | 何时失效 |
|---|---|---|
| 提交图窗口 | 30 秒 | 仓库写操作、主动刷新、HEAD 移动（键含 HEAD） |
| 仓库信息 | 60 秒 | 仓库写操作、主动刷新 |
| 工作区快照 | 0.5 秒 | 仓库写操作、HEAD 移动（键含 HEAD） |
| 仓库发现结果 | 60 秒 | 该仓库（含其祖先与后代所在的工作区）发生写操作 |
| 提交统计与提交信息 | 清理周期 | 换仓库、清理周期到 |

写操作只作废**目标仓库及其祖先与后代**的缓存：子模块的写会改变父仓库的变更列表，链接工作树与主仓库的状态互为镜像。

### 读取代价

- 只读命令跳过可选加锁，不阻塞写操作，也不在仓库里留下锁文件。
- 合并状态读 `MERGE_HEAD` 文件判定，不起 git 子进程。
- 工作区快照、HEAD、分支同步等高频取值一律走文件系统读取。
